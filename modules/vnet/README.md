# vnet module

Provisions a VNET, its subnets, and (optionally) a per-subnet NSG with
custom rules.

## Why per-subnet NSGs

Azure doesn't give subnets an implicit deny, so `create_nsg` defaults to
`true` — opting out is something a caller has to do on purpose. Rules live
on the subnet object itself rather than in a separate variable, since a
"data" subnet and an "app" subnet basically never want the same rule set
and this keeps them from fighting over one shared NSG.

## Usage

```hcl
module "vnet" {
  source = "../../modules/vnet"

  resource_group_name = "rg-opella-dev-eastus"
  location             = "eastus"
  vnet_name            = "vnet-opella-dev-eastus"
  address_space        = ["10.10.0.0/16"]

  subnets = [
    {
      name             = "snet-app-dev"
      address_prefixes = ["10.10.1.0/24"]
    }
  ]

  tags = {
    environment = "dev"
    project     = "opella"
  }
}
```

See `examples/basic` for a fuller example with NSG rules and service
endpoints.

## Testing

```bash
terraform init
terraform test
```

Uses the built-in test framework with a mocked provider, so it runs without
Azure credentials — checks subnet count, that NSGs only get created when
requested, and that rules land on the right subnet.
